Problem

Evacuation behaviour depends on where pedestrians begin, which exits are available, how groups are assigned, and how movement parameters are configured. The project was developed to compare these factors through one repeatable workflow.

My contribution

  • Imported and prepared the walkable building geometry from a WKT file.
  • Defined nine exit polygons and configurable pedestrian spawn areas.
  • Created scenario-specific rules for group placement and exit assignment.
  • Used JuPedSim distribution utilities to generate valid initial positions.
  • Used NumPy, Numba, and ThreadPoolExecutor for selected setup calculations.
  • Exported trajectories to SQLite and generated notebook animations.

Simulation methodology

Geometry

The walkable area is loaded from HC.wkt, with exits and spawn areas defined explicitly.

Scenario logic

Each case can change active spawn areas, group sizes, available exits, and walking parameters.

Outputs

The notebook records trajectories, evacuation time, runtime, and animations for comparison.

Representative visual

Engineering outcome

The project provides a reusable setup for comparing evacuation configurations instead of evaluating only one simulation. Geometry, spawn configuration, exit logic, movement parameters, and output generation remain separated so the workflow can be extended more easily.

Limitations and next steps

This is an educational pedestrian-dynamics study rather than a certified safety assessment. Exit selection is based partly on centroid distance and scenario-defined constraints, and the simulation has not been calibrated against measured evacuation data. Useful next steps include path-aware exit selection, sensitivity studies, additional geometries, and experimental validation.
