Problem

The Traveling Salesman Problem has a rapidly growing search space. Distributed optimization can reduce runtime, but it introduces communication, synchronization, load-distribution, and scaling challenges.

My contribution

  • Implemented distributed parallel tempering using C99 and MPI.
  • Used two-opt route modifications with Metropolis acceptance.
  • Precomputed a distance matrix to reduce inner-loop cost.
  • Designed an alternating neighboring-rank exchange pattern.
  • Automated strong-scaling runs and performance figures.

Parallel methodology

Search

Replicas at different temperatures balance local improvement with wider exploration.

Communication

Neighboring replicas exchange routes through an ordered alternating pattern.

Benchmarking

The total number of replicas remains fixed while the MPI process count changes.

Representative results

Results and limitations

  • The tested Berlin52 configuration reported a 20.7× speedup on 24 cores.
  • Reported parallel efficiency was approximately 86% at 24 cores.
  • The timings are specific to the tested cluster, compiler, MPI version, and solver settings.
  • The search is stochastic, so repeated runs with several random seeds are required for wider conclusions.
  • The recorded values describe the completed course study, not a general performance guarantee.

Possible extensions

Follow-up work could include hybrid MPI/OpenMP execution, CUDA acceleration, runtime-configurable parameters, additional TSPLIB datasets, and repeated-seed uncertainty statistics.
