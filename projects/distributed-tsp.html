Problem

The Traveling Salesman Problem has a rapidly growing search space. Distributed optimisation can reduce runtime, but it also introduces communication, synchronization, load-distribution, and scaling challenges.

My contribution

  • Implemented a distributed parallel-tempering search using C99 and MPI.
  • Used two-opt route modifications with Metropolis acceptance.
  • Precomputed a distance matrix to reduce inner-loop lookup cost.
  • Designed an alternating neighbouring-rank exchange pattern.
  • Automated strong-scaling runs and performance plots.

Parallel methodology

Search

Replicas at different temperatures balance local improvement with wider exploration.

Communication

Neighbouring replicas exchange routes through an ordered alternating pattern.

Benchmarking

The total number of replicas remains fixed while the MPI process count changes.

Representative results

Results and limitations

  • The tested Berlin52 configuration reported a 20.7× speedup on 24 cores.
  • Reported parallel efficiency was approximately 86% at 24 cores.
  • Communication overhead increased as more MPI processes were used.
  • The timings are specific to the tested cluster and solver settings.
  • Because the search is stochastic, repeated runs are needed for wider conclusions about solution quality.

Next steps

Planned extensions include hybrid MPI/OpenMP execution, CUDA acceleration, runtime-configurable solver parameters, and comparisons across additional TSPLIB datasets.
